# Vangers на Switch: рабочие заметки

Краткий журнал наблюдений. Обновляется по ходу. План и анализ осуществимости: `SWITCH_PORT_PLAN.md`.

## Как собирать и ставить
1. `build-switch.bat` - сборка (`clean` - с нуля), результат `out\switch\vangers\vangers.nro`.
2. `make-sd-folder.bat [E:]` - папка `sd\` (nro + данные GOG) и при желании сразу на SD.
3. Запуск ТОЛЬКО через title takeover (hbmenu, удерживая R при старте игры). Из Album (applet-режим) памяти мало -> перезагрузка консоли.
4. Логи: `sd:/switch/vangers/stdout.txt`, `stderr.txt`. При вылете: `sd:/atmosphere/crash_reports/*.log`; адреса расшифровываются так: `addr2line -f -C -e Vangers/build-switch/src/vangers.elf 0x<смещение vangers+0x...>`.

## Что работает (проверено на железе)
- Сборка devkitA64 16.1 / libnx 4.12, запуск из hbmenu (R-takeover).
- Главное меню, выбор мира, вход в игру, пауза (Minus), выход в меню и из игры. Не выкидывает из сна.
- Игровая область видна (после обхода, см. ниже), ездить можно по D-pad; FPS на глаз нормальный.
- Курсор правым стиком; клик физической A (в меню всегда), ZR (всегда). Minus = Esc/пауза.
- HUD, минимальная карта, таймер.

## Найдено и исправлено
- newlib: макросы `_X`/`_N`/... из ctype.h -> `switch/switch_compat.h` (включается принудительно, после libstdc++).
- Depfiles с `D:/...` у devkitA64 на Windows -> `CMAKE_DEPENDS_USE_COMPILER FALSE` до `project()`.
- Порядок статических библиотек -> `--start-group`.
- Нет `scandir`-ветки для Switch -> включена unix-ветка в `global.h`, `moveland.cpp`, `ivmap.cpp`.
- GOG-скрипт интерфейса `oftr.scb` старее движка (нет `FpsTrig`) -> NULL-разыменование в `iPrepareOptions` -> запасные триггеры в `iextern.cpp`.
- Кнопки SDL названы по Xbox-раскладке: SDL "A" = физическая B. Клик перенесён на SDL "B" (физическая A).
- Агрессивные оптимизации выключены для Switch (`-fno-strict-aliasing -fwrapv -fno-fast-math -fno-tree-vectorize ...`), на случай UB в старом коде.

## Открытые проблемы
1. **Игровая область была чёрной - обход работает, причина не найдена.** 3D-слой рисуется верно, а 2D-слой интерфейса приходит с заливкой индекса 72 (почти чёрный) на всю область вида с самого первого кадра гонки (до любой отрисовки кадра; из xbm-файлов GOG эта заливка не берётся). Обход: в `XGR_Screen::blitRgba` этот индекс внутри окна игры считается прозрачным (`viewKeyIndex`, цвет запоминается на первом кадре гонки; не действует в полноэкранных режимах). Побочный эффект: чёрный фон меню паузы внутри окна тоже станет прозрачным. Корневую причину искать позже. Временная диагностика (`DIAG`, `DIAGPIX` в `src/road.cpp`) пока оставлена.
2. **Левый стик не управлял машиной.** Причины (исправлено в коде, ждёт проверки): а) при старте игры `iEXT_INIT_JOYSTICK` перезаписывает режим стика опцией из GOG-скрипта (по умолчанию "нет"); б) кнопка 1 (A) по умолчанию работала как "переключатель стика" и отключала аналоговую езду при ускорении. Теперь на Switch: режим `JOYSTICK_Joystick` и переключатель на несуществующую кнопку.
3. **Прыжок** (на клавиатуре W, `iKEY_ACTIVATE_KID`: держать - копить, отпустить - прыжок) был не назначен. Теперь ZL (виртуальная кнопка, триггер как кнопка). ВАЖНО: старый `controls.dat` на SD-карте перебивает новые умолчания - его нужно удалить (`sd:/switch/vangers/data/controls.dat`, `options.dat`).
4. **Треск звука** (подозрение на нехватку ресурсов потока аудио). clunk работал с периодом 512 кадров (~11 мс) - увеличен до 2048 на Switch. Проверить, ушло ли.
5. **Настройка управления.** В игре есть экран Controls с переназначением (мышь = курсор правого стика); кнопки контроллера и триггеры ZL/ZR ловятся. Не проверено. Сделать удобные профили/пресеты, если штатного не хватит.
6. Ввод текста (имя пилота, чат): нужна экранная клавиатура (swkbd libnx) или экранная клавиатура движка.
7. Нет пункта 60 FPS в меню (в GOG-скрипте его нет; заглушка есть).
8. Не назначены: смена цели, оружие 1-4. 
9. Не проверено: видеоролики (ffmpeg), производительность и расход памяти (по ощущению игра легче многих портов), сохранения на SD (`savegame/` создаётся рядом с данными).
10. Мелочь: `Strange deltas clockDelta` в логе (таймер), шум libnx SDL в `stderr.txt` ("layout is already done"). Очередь событий: при переполнении события теперь отбрасываются (раньше аварийный выход во время загрузки).

## Идеи
- Сборка того же SDL2-кода на ПК как быстрая проверка меню/управления (эмуляторы Switch не рекомендуются: результат ненадёжен).
- После починки видимости: оптимизации для FPS (понижение разрешения, 30 FPS).

## Переназначение клавиш (открыто, низкий приоритет)
- Раскладка по умолчанию устраивает, переназначение пока не нужно.
- После правок (кнопки геймпада в захвате, «−» = отмена) кнопки всё равно не меняются.
- В iscreen.cpp добавлен лог `keycapture: event ...` в stderr: показывает, доходят ли события до экрана захвата.
- Ввод текста (имя сохранения): свой набор символов на D-pad (см. input_string_quant).
